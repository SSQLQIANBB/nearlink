# 基础功能与无人值守优先实施

更新：2026-09-28。依据用户最新要求：当前没有多台电脑，先完成基础功能开发，重点推进远程解锁、开关机和无人值守。原 S0 的物理设备验证继续保留，不作为所有代码开发的前置阻塞，也不标成已通过。

## 本批交付

F14 设备重命名已实现，版本 `0.6.0-beta.2`：

- 个人中心“我的远程设备”支持编辑、保存、取消；Web 和桌面均可管理已有设备。
- `PATCH /api/remote-control/devices/:id` 接受严格对象 `{ alias: string }`，去除首尾空白，限制 1–80 个 UTF-16 代码单元，拒绝控制字符和额外字段。
- 更新条件包含 `id + ownerUserId + revokedAt:null`，不存在、非本人或已撤销设备统一返回 404；返回安全设备字段，不返回设备密钥。
- 客户端中止旧列表请求；取消或账号切换后丢弃迟到的修改结果。失败提示刷新确认，不声称取消网络请求等于数据库回滚。
- 名称保存在服务器；其他端刷新列表后可见，暂不实现即时推送。无需数据库迁移、新环境变量或原生权限。

验证：`pnpm test` 通过后端 217 项、前端 305 项及发布脚本 11 项；`pnpm typecheck` 通过。随后补充跨域 PATCH 预检回归，远控路由 15 项全部通过（后端累计 218 项）。`git diff --check` 通过。

## B02 已交付部分（0.6.0-beta.3）

设备名称/ID 搜索、登记状态/系统组合筛选、清除筛选及空结果提示已实现；筛选基于当前接口最多 100 台已加载设备，达到上限明确说明限制。服务器分页和分组仍待后续扩展。

会话窗口新增适应窗口、50%–200% 缩放、统计显示开关，并按用户+设备+结构版本保存本地偏好。改动设置会暂停输入；原始大小指接收视频像素大小，不承诺等同远端物理显示器像素。缩放不改变编码分辨率、码率或带宽。动态画质档位待原生编码器支持运行时配置后接入，不提供未生效的选项。

无需服务器迁移或新增配置。当前不跨客户端同步偏好。无人值守及电源操作没有在此批次实现或启用。

## 授权管理增量（0.6.0-beta.4）

新增本机记忆授权查看与逐条恢复确认。原生验签后仅输出安全元数据；删除按当前账号和记录摘要定位，使用现有确认 epoch 防止在途批准重新写回。网页层不能新增或扩权。此项是授权可见性和撤销基础，不是 B03 的可信主控设备绑定；完整无人值守仍待独立协议与本机启用策略实现。

## B03 无人值守第一阶段详细设计（待实现）

默认关闭，设备所有者必须在被控机原生确认启用，显示允许的主控设备和观看/控制范围。第一版优先绑定可信主控设备密钥；固定访问密码是后续独立方案，不复用账号密码、系统密码或现有长期协助许可。

### 后端

新增 `RemoteAccessPolicy` 数据表：策略 ID、hostDeviceId、ownerUserId、controllerUserId、controllerDeviceId、scope、revision、enabled、createdAt、revokedAt。主控设备撤销、策略关闭或范围收缩均使旧 revision 失效。针对设备和主控做尝试限额；表建立外键/索引并提供可回滚迁移。

新增策略服务与 REST：创建/撤销需要近期重新认证，以及被控设备签名的一次性启用证明；后端校验设备归属、证明目的、nonce 和有效期。列表不返回密钥。会话请求明确标识 `interactive` 或 `unattended`，不得用“没找到弹窗”自动切换为无人值守。

现有签名授权证明增加独立协议版本：绑定策略 ID/revision、主控设备、被控设备、会话 ID、scope、过期时间和 nonce。继续使用短期会话租约与撤销通道；不能签一个长期通用控制令牌。协议升级时递增产品次版本并配套更新原生端严格解析器。

### 原生端

本地安全存储保存用户确认的策略摘要和 revision；收到请求时同时验证服务器签名、主控设备证明、本地策略和系统能力。没有任一条件就拒绝，不回退到自动批准。允许范围变更需本机再次确认；本地关闭即时停止受该策略授权的采集和输入，服务器暂时离线时也必须能关闭。

扩展当前授权状态机，保留可见连接状态、停止入口、失联清理和输入焦点约束。第一阶段不宣称支持登录前、锁屏输入或 FileVault 预启动。

### 界面与验收

个人中心显示“无人值守访问（关闭/开启）”、可信设备列表和每设备访问范围；初次绑定显示本机确认，撤销可单独操作。重连仍须重新取得短期授权。测试覆盖跨账号、错误主控密钥、撤销设备、策略 revision 过期、重放 nonce、权限提升、本地策略丢失、租约过期，以及降级客户端不能绕过检查。

## B04 电源动作详细设计（待实现）

不把电源操作当作键盘快捷键转发。新增独立 `power.lock`、`power.restart`、`power.shutdown` 权限，旧 `control` 不自动继承。每个动作包含 actionId、设备、会话、策略 revision、动作枚举、有效期和签名；原生执行器去重并校验系统权限。禁止远端提交任意 shell 命令或参数。

主控先确认目标和动作；关机/重启在被控端显示倒计时和取消入口，默认不强制结束有未保存内容的应用。动作状态区分“已请求、已接受、已取消、执行失败、结果未知”；断线不能显示为关机成功。重启恢复通过新连接的启动标识确认，不仅依赖旧连接消失。

服务器保存不含敏感输入的审计记录。开发时默认 dry-run；自动测试只验证动作分发与结果，不执行本机锁屏/关机。真正系统操作进入单独手工验收步骤。

## B05–B07 平台与服务器边界

Windows 需要服务与交互桌面进程分离，限制 IPC 调用者和命令集合。服务运行并不意味着能直接操作登录桌面；登录前采集、UAC 和安全桌面必须单独实现与验证。

macOS 区分用户会话后台代理和特权辅助服务；采集、辅助功能和系统操作各自检查权限。睡眠唤醒、已登录锁屏、退出登录和磁盘加密预启动是不同状态，界面不得统称“可解锁”。Apple 文档说明部分新系统/硬件组合有额外恢复途径，不能据此推断现有客户端已支持。

网络唤醒必须有目标网络内的在线代理或受支持硬件。服务器仅投递经设备授权的任务；代理只向已绑定网卡及允许子网发送有限次数的唤醒包，不能接受任意广播目标。发送成功仅代表已发包；收到目标设备重新上线证明后才显示唤醒成功。

现阶段后端继续单活跃进程；此规划不要求立即新增公网端口。后台服务安装、WOL 代理网络部署以及任何系统登录集成均是后续独立交付，不在本次改名功能中安装或启用。多实例需要另行完成共享所有权与跨节点撤权。
