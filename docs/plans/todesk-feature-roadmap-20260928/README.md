编制日期：2026-09-28。代码基线：`221993e`，产品版本 `0.5.0-beta.13`。本次交付是规划文档，不代表已实现、已部署或通过验收；不修改产品版本、功能开关或生产配置。

## 1. 使用方式与范围

- 本文：功能清单、现状差距、优先级、阶段、验收标准及人员投入。
- [代码层实施方案](./IMPLEMENTATION.md)：工作包 W01–W16、文件落点、协议、数据模型、接口、测试和交付拆分。
- [服务器配置与发布方案](./SERVER.md)：现有部署、资源测算、网络端口、TURN、配置归属、扩容、监控、备份与回滚。

功能来源为 [ToDesk 官方功能页](https://www.todesk.com/special.html)，读取日期 2026-09-28。按正文顺序核对出 **72 个条目**：基础控制 17、网络画质 9、协作 13、外设 8、运维 12、安全 13。下表用自有产品的实施用语概括，编号 F01–F72 对应原页面顺序，保留页面中语义重复的条目以便追踪。官网导航中的团队管理、AI 助手另列 E01/E02，不混入正文计数。

官网描述只用于识别用户需求，不据此推断对方内部实现或承诺相同性能。本项目沿用 Vue 3、Tauri 2、Rust 原生监督、GStreamer 引擎、Koa、Socket.IO、MySQL、Redis、coturn 和七牛存储；先完成可靠的办公远控，再扩展企业、移动端和专业外设。

## 3. 优先级、状态和阶段定义

- **P0**：开放远控前必须完成，含授权、真实传输、停止释放、稳定性、TURN 和发布门槛。
- **P1**：办公远控的主要用户价值，核心链路通过后开发。
- **P2**：团队、协作和规模化增强。
- **P3**：驱动、特殊平台或高性能专项，先验证可行性，再承诺日期。
- **待验收**：有远控实现或联调证据，未满足对应发布门槛。
- **部分**：有可复用模块或子能力，仍需开发并验收。
- **新增**：在本次核查范围内未找到完整能力实现；不以相似页面视为完成。
- **研究**：需先完成平台/驱动/协议可行性验证。

阶段：S0 基线收口；S1 办公远控；S2 协作与团队；S3 移动端/运维/多区域；S4 专业专项。一个条目可跨多阶段，后续阶段明确保留，不以首个子能力交付冒充全部完成。

## 7. 统一发布门槛

每条功能至少有：平台与版本、角色/权限、代码完成证据、自动测试、两端实机操作、异常/撤销/停止、服务器依赖、回滚方案、功能开关、验收负责人及日期。清单状态升级为“可开放”必须同时满足这些条件。

建议的首轮性能目标（项目自定，待 S0 标定，不是官网或现有产品实测结果）：在指定局域网和标准办公场景达成 1080p/30fps 档位；视频实际帧率随静态内容可降低。RTT ≤50ms、丢包 ≤1% 的受控跨网环境中，输入到画面可见变化 p95 ≤200ms；限速 1Mbps 或丢包 5% 时允许降低分辨率，但不得出现旧输入集中回放。所有数值记录硬件、编解码器和测量方法。

安全退出按事件分别验证：本机停止输入立即关闭，目标 1 秒内结束采集/输入；远端撤权通知目标 2 秒内到达；失联最迟在现有 15 秒授权租约失效后不能继续采屏/执行输入（更短 watchdog 保持生效）。这些是新增验收目标，必须测量实际释放时间，不能只看 UI 状态。

新增较大功能/重要协议/架构变更在对应提交中升级次版本，普通迭代递增 alpha；所有自有版本同步，界面标“内测版”，中文提交说明。按 [发布规范](../../DESKTOP_RELEASE.md) 执行。示例版本只能在合并前依据实际最新版本确定，不能预占或覆盖标签。
