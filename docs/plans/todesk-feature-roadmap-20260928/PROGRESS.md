## 本机设备识别 / 无人值守身份基础

版本 `0.7.0-beta.1` 新增独立用途的本机设备识别证明：原生只读取已有系统凭据密钥，为 `identify-device` 挑战签名；服务器验签后按公钥指纹、当前账号、平台及未撤销状态查找登记记录。没有登记或无法读取密钥时提示失败，不创建或重建身份。

界面提供显式“识别本机设备”和取消入口，成功后显示“本机（已验证）”；本机协助处于离线状态时自动选中匹配的 macOS 设备。成功登记也会设置当前会话内的本机标记。刷新发现记录撤销/缺失、切换账号或重建身份后清除标记。识别标记只辅助选择，不用于服务端授权，也不表示在线或可控。

新接口：`POST /api/remote-control/device-identity-challenges` 与 `POST /api/remote-control/device-identity/verify`。挑战 30 秒有效、每账号每分钟最多申请 5 次，Redis 原子消费绑定账号、sid 与用途。登记/识别证明互不通用；新原生命令仅主窗口可调用，网页不能传入任意签名消息。旧客户端不显示识别入口。

无需数据库迁移、新端口或新环境变量，沿用 Redis SET/EVAL 权限。新增证明用途触发产品次版本升级，但现有远控会话协议版本仍为 1；登记和普通协助接口保持兼容。服务器需要先部署新增接口，再使用新版桌面识别功能。

验证：后端 222 项、前端 319 项、发布脚本 11 项通过；隔离 Redis 集成 7 项通过；Rust 133 项通过、2 项忽略；类型检查和差异空白检查通过。Node/Rust 共用签名向量，覆盖用途隔离、过期、账号/sid 绑定、重放、撤销设备查询、取消与切换账号。尚未进行新版安装包和多设备验收。

本批仍未实现可信主控设备绑定、无人值守策略或后台服务，不改变远控发布闸门。完整无人值守仍按 B03 设计继续推进。

## 主控连接设备认证 / 无人值守身份基础第二批

版本 `0.8.0-beta.1`：桌面主控已登记/识别本机时，远控握手携带 `controllerDeviceId`；服务器签发绑定当前账号、sid、authVersion、实例 ID、Socket ID 和连接代次的挑战，原生验证内置服务器公钥、完整连接字段与本机设备密钥，再签发独立用途 `native-controller-binding` 证明。

声明了设备的连接，在完成证明验证前不能创建会话；验证失败直接关闭，不回退为普通连接。证明只消费一次，连接 30 秒未完成认证则关闭；每连接最多 4 次认证命令，沿用队列/载荷限制。已通过认证的连接每 5 秒检查登记撤销和密钥版本（同时最多一个周期检查），每次授权检查与租约续期也检查设备身份。断线清除内存认证状态，旧证明不能用于新连接。界面显示“主控设备身份已验证”，不会因此启用采集或键鼠。

普通浏览器和未登记/识别本机的桌面仍走既有逐次/记忆确认协助流程，不视为可信设备或无人值守。实例 ID 继续独立于设备 ID；设备绑定只保存在当前服务器连接上，没有持久化信任策略，也不修改已有会话/数据库字段。停止媒体仍遵循既有通知及短租约机制，5 秒巡检不是跨网络实测断流保证。

服务器与新版桌面需配套支持 `remote:controller-challenge` / `remote:controller-proof` 及原生 `remote_control_bind_controller`。旧客户端不受新增可选握手字段影响；新客户端已有本机身份却缺少原生绑定能力时提示升级，旧服务器拒绝新字段时连接失败，不自动降级。沿用签名密钥、登录校验及单活跃进程配置，无数据库迁移、新端口或新秘密变量。产品因新增连接认证协议升级次版本；既有媒体协议仍为 1，公开远控开关不变。

验证：后端 234 项、前端 323 项、发布脚本 11 项通过；Rust 135 项通过、2 项忽略；前后端类型检查和差异检查通过。共用 Node/Rust 签名向量；Socket 接线测试覆盖未验签请求、认证成功、撤销断开及认证超时；适配器测试覆盖失败不降级和断线后的迟到签名。尚未进行新版安装包与多设备验收。

完整无人值守仍需被控机本地启用、可信主控设备绑定策略、独立策略 revision 与撤销路径；电源/解锁/后台服务未在本批开放。

## S0 / T03：群与协作房间授权补齐

状态：**代码及自动测试完成，部署及多设备验收待完成**。

### 已实现

- 群房间加入、群消息、媒体开始/结束/加入/离开、群 WebRTC 信令、屏幕标注及麦克风管理统一查询 MySQL 群成员资格；查询失败拒绝操作。
- 信令发送方和接收方必须是同一群、同一媒体类型、同一 `startedAt` 会话的已入会 Socket；接收方成员资格再次查询，禁止把任意 Socket.IO 房间名作为目标。
- 入会及 offer/answer/ICE 必须携带当前会话 `startedAt`。客户端丢弃旧会话成员通知和信令，避免上一场会话的延迟消息干扰新会话。
- HTTP 退群、删群、权限更新与 Socket 群操作按群串行，避免查询授权后与退群写入交错。退群/删群后移除该账号所有本地连接的订阅和媒体房间，通知参与者关闭已有连接。
- 视频和屏幕共享页面收到撤权、群服务错误或断线后关闭 PeerConnection、停止本地原始/处理后媒体流、移除监听并退出页面；撤权同时清除重连订阅。
- 群会话结束限创建该会话的 Socket；Redis 使用期望值比较删除，旧连接的延迟清理不能删除新会话。
- 麦克风管理校验群主身份、同会话关系及目标成员，持久化发言权限；普通成员不能越权控制他人。

### 服务器与升级要求

本批不新增数据库表、环境变量或监听端口，沿用现有 MySQL、Redis、`/meeting` WebSocket 配置。Redis 账号需要支持现有读写和 `EVAL` 命令，比较删除通过 Lua 完成。

当前群成员在线表、媒体注册表、操作队列和撤权通知均在进程内；部署必须保持单个活跃后端进程，不可仅增加进程数或容器副本。多实例需要共享会话所有权、跨节点撤权广播和分布式并发控制，是后续工作。

`startedAt` 是本版群媒体协议必填字段，旧版客户端不能继续加入群媒体。升级前结束存量群会话、停止旧后端，配套部署 `0.6.0-beta.1` 后端与网页/桌面客户端，并要求网页刷新、桌面升级；不能混跑新旧后端。部署后先验证普通成员正常加入，再验证非成员拒绝、退群/删群释放和重连不再订阅。不存在自动兼容降级。

回滚需先结束会话并停止服务，再成套恢复前后端版本；无需回退数据库结构。旧版本缺少本批授权防护，回滚后应在修复重新上线前暂停群媒体入口，不能视为等价安全回滚。

### 仍需人工验收

| 场景 | 验收操作与证据 |
| --- | --- |
| 正常通话 | 两台实际设备分别加入视频和屏幕共享，确认双向媒体、标注、停止和重新开会 |
| 非成员 | 第三个非成员账号发送入房与信令请求，确认没有媒体成员列表、标注及群内容泄露 |
| 退群/删群 | 通话中通过 HTTP 退群/删群，记录各设备轨道停止、PeerConnection 关闭及实际停止收发时间 |
| 多端与断线 | 同一账号两端在线，撤权后两端释放；断网重连不自动恢复已撤销会话 |
| 故障 | 数据库/Redis 临时不可用时拒绝新增操作，验证客户端释放及恢复后重入行为 |
| 升级 | 新版正常连接，旧版群媒体被拒绝并提示升级；旧会话迟到信令不能影响新会话 |

已有 P2P 媒体依靠配套客户端收到事件后关闭；信令服务不能收回恶意客户端已交换的媒体密钥，也不能强制阻止其继续向另一恶意端传输。群主静音同样不是媒体服务器强制静音。若要求对不可信客户端强制断流，需要后续媒体中继/SFU 授权设计。
